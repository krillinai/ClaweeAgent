# P11 文件引用与指定 MCP 方案设计

日期：2026-11-09。状态：已完成仓库适配评审，待开发。本文由 Clawee 原仓库的同名方案复制修订，作为 ClaweeAgent 开源版本的开发基线；原始方案文档保持不变。

本轮核对基线：ClaweeAgent `7f3754bbffc0198d172f8a0c1d12568e612ce4b1`，aigateway `9340d7dbffa15f3f0a36827d8e261f0bd676e4c1`。本地 Runtime 搜索已完成隔离验证，真实文件读取、MCP 调用及跨平台联调留待开发验收。

## 1. 目标与核心决策

用户在任务输入框输入 `@`，可以搜索并引用当前工作区文件，也可以点名本次任务要使用的 MCP。

首版采用以下方案：

| 决策 | 实现口径 |
| --- | --- |
| 统一入口 | `@` 弹出一个候选列表，按“文件”“MCP”分组 |
| 输入框 | 保留现有文本框，选择后插入可编辑文本 |
| 文件引用 | 插入相对路径，Agent 根据任务读取文件当前内容 |
| 指定 MCP | 明确要求本次请求优先使用选中的 MCP，允许其他工具辅助 |
| 执行方式 | 沿用现有 prompt、任务队列和 Runtime 调用链路 |

“指定 MCP”属于给 Agent 的使用要求，首版不提供程序级的必调用保证或“只能使用这个 MCP”的工具隔离。成功使用必须以真实工具调用及结果为准，不能仅凭模型回复判断。

范围限定为当前工作区内的普通文件，以及现有 MCP 列表中已配置、已启用的服务。目录引用、行范围、跨工作区搜索、MCP 内单个工具选择和富文本标签留到后续有明确需求时处理。

本期功能在 ClaweeAgent 的 Web、daemon 和共享协议内实现。aigateway 已有 MCP 目录与授权接口满足当前方案，无需新增 Gateway 接口或数据库迁移。实现通过现有 HTTP/MCP 接口接入，不依赖相邻仓库的源码目录。

依据：`client/config/codex-runtime.json`、`client/config/codex-app-server-schema/rust-v0.151.0/stable.json`。2026-11-09 已使用本仓库内嵌的 Codex 0.151.0，在 macOS arm64 上以临时工作区和独立临时 `CODEX_HOME` 完成实际搜索验证，结果如下：

| 验证项 | 实测结果与实现要求 |
| --- | --- |
| 文件名与路径匹配 | 中文、空格、双引号和相对路径搜索可用；结果包含 `root`、相对于该根目录的 `path` 和 `match_type` |
| 非 Git 工作区忽略规则 | 样例中的 `.gitignore` 未排除指定文件，`node_modules` 下的文件也能返回；daemon 必须执行现有显式忽略目录过滤 |
| 符号链接 | 指向工作区内、外文件的符号链接都可能返回；daemon 必须检查真实目标及普通文件类型 |
| POSIX 反斜杠文件名 | Runtime 能返回包含字面量反斜杠的文件名；路径适配必须保留其原义 |
| 结果数量 | 80 个同类匹配文件的样例返回 50 项；这是本轮观测值，不能把 Runtime 结果视为全量枚举，也不能保证过滤后始终有 20 项 |

上述验证确认了本机搜索接入可行，尚未覆盖 Windows、Linux、真实 Agent 文件读取或 MCP 调用。开发时将这些样例固化为适当的自动化验证，并在对应平台完成联调。

## 3. 输入框交互

### 3.1 触发与筛选

1. 在行首、空白字符后输入 `@` 时打开候选；`name@example.com` 这类正文不触发。
2. 紧随 `@` 的当前输入作为搜索词，支持文件名、相对路径和 MCP 名称。
3. 文件由 daemon 搜索；MCP 在前端对现有列表按展示名、稳定服务名做不区分大小写的包含匹配。
4. 列表按“文件”“MCP”分组，文件显示名称和相对路径，MCP 显示展示名及稳定服务名。同名文件通过路径区分。
5. 仅输入 `@` 时，显示已启用 MCP，并提示“输入名称搜索工作区文件”；有搜索词后再请求文件搜索，不在打开菜单时枚举整个工作区。

复用现有弹层样式与候选操作方式：方向键切换，回车或 Tab 选择，Esc 关闭，鼠标可点击。键盘事件按以下顺序处理：

1. 在所有候选选择、方向键和提交分支之前检查输入法组词状态；组词期间交由输入法处理，不切换或选择候选，不提交任务。
2. `@` 候选打开时，普通回车有候选则选择；正在加载、无匹配或错误状态时拦截普通回车，避免落入任务提交。无候选时可先按 Esc 关闭菜单，再按回车发送正文。
3. Tab 仅在存在可选候选时执行选择，Shift+Enter 沿用原有换行行为。

当前 `Composer` 的输入法检查位于 `/` 候选选择分支之后，新增交互时应把保护前置；其余 `/` Skill 交互沿用现有行为。

每次只替换光标处的 `@搜索词`，保留前后正文，插入后补一个空格并恢复光标。删除、复制、粘贴和草稿恢复均按普通文本处理。

已选中的 Skill 在现有实现中以隐藏前缀保存在完整 prompt 中。触发区间、文本替换和光标恢复沿用现有可见文本与完整 prompt 的偏移换算，不能把 textarea 的光标位置直接用于完整 prompt。

### 3.2 插入内容

| 类型 | 插入文本示例 | 说明 |
| --- | --- | --- |
| 文件 | `@"docs/需求.md" ` | 统一使用带引号的工作区相对路径，支持中文和空格 |
| MCP | `本次请求请优先使用 MCP：enterprise_rose ` | 与已有 MCP 菜单共用 `connectorInsertText`，统一注明本次请求范围并保留稳定服务名 |

文件插入值按 `@` 加 `JSON.stringify(relativePath)` 生成，目录分隔符统一为 `/`。Windows 只转换作为目录分隔符的反斜杠；macOS/Linux 保留文件名中的字面量反斜杠，由 JSON 字符串转义表达，不能全量替换为 `/`。双引号、换行等字符同样由 JSON 字符串转义，插入文本表达的是原始文件路径。

MCP 有展示名时插入 `本次请求请优先使用连接器「展示名」（MCP：稳定服务名） `。已有 MCP 菜单与 `@` 候选使用同一函数和同一文案。

例如最终正文可以是：

```text
根据 @"docs/登录需求.md" 修改 @"src/login.ts"，本次请求请优先使用 MCP：enterprise_rose 查询相关内部规范。
```

`@` 是选择入口；MCP 选择后直接变成已有自然语言指令。首版不增加另一套 MCP 标记语法，也不解析整段正文来识别、维护隐藏引用对象。

### 3.3 状态与切换

- 文件搜索输入防抖 200ms，最多显示 20 个文件。使用递增请求序号判定有效响应，不能只比较项目 ID 和关键词；A→B→A 的连续搜索也只能接受最后一次请求的结果。
- 关键词变化时立即使旧请求失效，再等待防抖；清空关键词、关闭候选、切换项目或会话、改变账号或 Agent、卸载 Composer 时同样使旧请求失效。响应只有在请求序号、候选打开状态和当前作用域均有效时才能写回。
- 项目目录替换或 `canonicalCwd` 变化时，即使项目 ID 未变，也应关闭候选、清空结果并使旧请求失效。
- 文件无匹配时显示“没有匹配的文件”，该状态仅表示本次 Runtime 返回结果经过过滤后没有可展示文件，不代表工作区不存在相关文件。搜索失败时显示“文件搜索失败，请重试”，仍可选择 MCP 和编辑正文。
- 未启用的 MCP 不进入 `@` 候选；安装、启用、授权继续使用现有管理入口。
- 当前页面没有可用项目时，不提供文件候选；MCP 能力按现有页面实际可用情况展示。
- 草稿沿用现有由 Gateway、账号、Agent、项目及会话组成的作用域。切换项目时恢复目标项目自己的草稿，原项目的引用文本保留在原草稿中；引用不自动从项目 A 搬入项目 B。
- 每份草稿内的相对路径按该草稿发送时的项目工作区解释；项目目录替换后也遵循这一规则，不保存文件内容快照。新任务沿用现有项目选择器，文件候选分组头显示当前项目名称；已有会话通过同样的只读名称标识工作区，无需开放额外的项目切换入口。
- `/` Skill 入口、筛选和插入方式沿用现有逻辑，候选键盘处理共用前置的输入法保护；同一时刻只打开一个候选菜单。已有 MCP 菜单继续复用同一插入函数。

## 4. 文件搜索接口与实现

### 4.1 对外接口

新增 daemon 接口，路径相对于现有 API 前缀：

```http
GET /workspace/files/search?projectId=<项目ID>&query=<搜索词>
```

```typescript
type WorkspaceFileSearchRequest = {
  projectId: string;
  query: string;
};

type WorkspaceFileSearchResponse = {
  files: Array<{
    name: string;
    path: string; // 相对于项目 canonicalCwd；目录分隔符为 /，POSIX 文件名中的反斜杠保留
  }>;
};
```

查询按项目 ID 定位工作区，不要求先创建会话，因此首页新任务和已有会话使用同一个接口。前端不传绝对路径或任意搜索根目录。请求校验、认证和错误封装沿用现有 daemon API。

请求先校验项目：不存在返回现有 `PROJECT_NOT_FOUND`（404），已归档返回 `PROJECT_ARCHIVED`（409），目录不可用返回 `PROJECT_DIRECTORY_UNAVAILABLE`（422）。目录是否可用应检查当前项目的目录状态及真实根目录，不能仅依赖持久化的 `canonicalCwd`。

项目有效时，空搜索词直接返回空列表；非空查询词最长 256 个字符，类型或长度不合法沿用 `VALIDATION_FAILED`（400）。搜索进程异常或超时通过现有 daemon 错误封装返回失败，不伪装为空结果。接口不返回文件内容。

### 4.2 daemon 搜索流程

1. 从项目管理器读取当前项目，检查未归档、目录可用，获得并核验可信的 `canonicalCwd`。
2. 调用固定版本 Runtime 的 `fuzzyFileSearch({ query, roots: [canonicalCwd] })`。
3. 将返回的 `root`、`path` 与本次请求根目录核对，按当前平台解释路径；拒绝绝对匹配路径、越界路径及无效路径。只保留 `match_type === 'file'` 的结果，并按路径段执行现有显式忽略目录过滤。
4. 解析真实目标，确认仍位于工作区内且为普通文件；过滤失效路径、目录、特殊文件，以及指向工作区外或显式忽略目录的符号链接。
5. 生成平台语义正确的工作区相对路径，保持 Runtime 的匹配顺序，去重后返回最多 20 项。过滤后不足 20 项正常，不追加全量遍历来补足数量。

Runtime 负责模糊匹配，daemon 负责最终结果范围。现有显式忽略目录集合（如 `.git`、`node_modules`、`.runtime`、`dist`、`build`）复用 `workspace-files/paths.ts` 中的定义；`.gitignore` 等附加规则由 Runtime 自身决定，不能承诺在所有工作区类型下均生效。匹配路径和解析后的目标路径都要检查显式忽略目录，避免符号链接绕过过滤。

路径检查复用现有忽略目录、真实路径和根目录边界检查等底层能力。现有 `validateRelativePath` 会将所有反斜杠替换为 `/`，不能直接用于需要保留 POSIX 字面量反斜杠的搜索结果；在新增搜索路径适配中处理平台分隔符与校验，保持既有文件接口的职责边界。边界判断使用路径关系，不使用简单字符串前缀判断。

### 4.3 搜索客户端与生命周期

每个 daemon 通过 `createCodexAppServerClient` 创建一个专用搜索客户端，使用当前 daemon 的 Runtime 路径、受管 `CODEX_HOME` 和 Runtime 环境。客户端实例可重复请求，底层进程在首次搜索时按现有机制延迟启动。

这里复用的是客户端工厂，搜索实例与 `server.ts` 中供模型列表和历史查询使用的 `codexAppServerClient` 分开，也不借用正在执行任务的 Host。现有请求客户端在任一请求超时时会终止该客户端进程并拒绝其全部待处理请求，因此共用实例会使文件搜索故障影响模型或历史查询。

专用搜索客户端沿用已有超时、进程失败及后续请求重新启动机制。普通输入只复用该实例；不为每次按键新建进程，不增加进程池、磁盘缓存或搜索会话系统。搜索服务失败通过接口返回，不影响正文编辑、MCP 选择和已有任务执行。

资源归属放在 `api/server.ts` 的组装层，搜索服务通过依赖注入使用客户端。daemon 关闭时，由既有资源释放入口关闭专用客户端一次；关闭后不再接受新搜索。该处涉及 daemon 连接清理，实施前需按本仓库约束说明具体改法并取得确认，文档修订本身不代表该代码变更已获确认。

## 5. 文件与 MCP 的执行语义

### 5.1 文件

选择文件只把路径写入正文，`RunRequest.prompt` 按现有链路提交、排队和保存。无需新增 `references` 字段、字符区间映射或数据库表。

在现有开发者指令中增加简短规则：用户以 `@` 加 JSON 字符串的形式点名当前工作区文件时，按 JSON 字符串转义含义理解原始相对路径，根据任务需要读取对应文件；不能将转义文本当作 shell 已转义的路径直接拼接命令。引用路径本身不包含文件内容，也不扩大访问权限。

文件在 Agent 实际读取时取当前内容；排队期间修改文件也遵循这一规则。文件被删除、重命名、没有读取权限或格式无法处理时，由 Agent 明确说明，不能声称已读取。首版不增加发送前的二次探测、内容快照或文件全文自动注入。

引用已有文件与上传附件分工明确：前者定位当前工作区文件，后者继续负责把外部文件带入任务。文件引用不自动转成图片输入，也不增加文档转换链路。

### 5.2 MCP

MCP 候选来自现有客户端可见配置，仅选择 `configured && enabled` 的服务。显示名称供用户辨认，执行指令包含稳定服务名，不能只靠展示名或列表序号路由。

补充现有点名连接器规则：

- 在权限和上层策略允许、且能力适合任务时，用户显式指定的 MCP 优先于默认连接器路由或默认企业知识库路由，必须优先调用该 MCP 完成相关步骤；其他工具可辅助。
- 未暴露、权限不足、调用失败或缺少所需能力时，说明具体原因，不得静默替换为另一个 MCP，也不得虚构调用结果。
- 只使用 Runtime 实际暴露的工具；配置已启用不代表当前会话一定有工具，更不代表绕过 Gateway 授权。
- 插入指令统一注明“本次请求请优先使用”，作用于本次请求；不修改全局启用状态、运行时工具白名单或其他会话配置。后续对话仍可能保留这段历史，首版不承诺上下文隔离。

这套规则属于提示词约束。验收应检查代表性任务的实际 MCP 工具事件，但不能据此对外承诺所有任务都必然调用成功。

## 6. 开发拆分

| 顺序 | 工作 | 完成标准 |
| --- | --- | --- |
| 1 | 固化 Runtime 样例并明确资源接入改法 | 复现本机已验证的路径、忽略规则和符号链接行为；补充对应平台验证；在修改 daemon 清理代码前取得具体方案确认 |
| 2 | 增加共享类型、独立搜索客户端、搜索服务与路由 | 新会话无需预创建；项目状态、路径语义、显式忽略目录及真实目标均被校验；客户端超时不影响模型和历史查询，关闭时被释放 |
| 3 | 增加前端搜索方法和 `@` 候选 | 分组可搜索选择；输入法保护、无候选回车、Skill 前缀偏移、请求序号失效和现有草稿作用域均通过验证 |
| 4 | 统一 MCP 插入文案、补充执行指令并联调 | 文件由 Agent 实际读取；MCP 指令注明本次请求并包含稳定服务名；显式选择优先于默认路由，实际工具事件或明确失败说明可核验 |
| 5 | 完成回归与客户端预检 | 下表场景通过，保留 `desktop:preflight:local` 结果 |

路由接线在 `client/apps/daemon/src/api/server.ts` 完成；MCP 候选继续由 `AppController` 传给 `Composer`。新增实现放在现有工作区文件、Runtime 和输入框职责边界内，不建设通用引用框架。

本方案不涉及 Electron Bridge、Gateway API、数据库迁移和依赖变更。专用搜索客户端的关闭接线按第 4.3 节单独处理确认，不扩展或重构其他 daemon 停机逻辑。

## 7. 验收与测试

| 场景 | 预期结果 |
| --- | --- |
| 新任务尚未创建会话，输入 `@需求` | 能搜索当前项目文件，选择后保留正确相对路径 |
| 同名文件、中文文件名、含空格或引号的文件名 | 路径可区分，插入文本完整，Agent 能正确定位 |
| macOS/Linux 文件名含字面量反斜杠，或 Windows 路径使用反斜杠分隔目录 | POSIX 文件名保留原义并正确 JSON 转义；Windows 目录分隔符正确转为 `/`，Agent 不读取另一个路径 |
| 多个引用、在正文中间插入、复制粘贴和草稿恢复 | 前后正文和路径不丢失，光标位置正确 |
| 已选中 Skill，在可见正文开头或中间插入引用 | 隐藏 Skill 前缀保留，触发区间、替换正文和光标位置正确 |
| 方向键、回车、Tab、Esc、中文输入法 | 候选操作正常，组词或选候选时不误发任务 |
| 候选打开并处于输入法组词状态，按方向键、回车或 Tab | 不切换或选择候选，不提交任务，按键交由输入法处理 |
| 文件搜索正在加载、无匹配或失败，且没有可选 MCP | 普通回车不提交任务；Esc 可关闭候选，关闭后可正常发送正文 |
| 输入邮箱、使用 `/` Skill、上传附件 | 原有交互保持正常 |
| 快速输入 A→B→A，或同词重复搜索，响应逆序返回 | 只接受最后一次有效请求的结果 |
| 清空关键词、关闭候选，或切换项目、会话、账号、Agent | 旧响应失效，不重新打开候选或覆盖当前结果 |
| 同项目 ID 替换工作目录，旧搜索随后返回 | 旧目录结果被丢弃，后续搜索仅使用新目录 |
| 项目 A 有含引用的草稿，切到 B 后再切回 A | B 恢复自己的草稿，A 引用仍留在 A 草稿；候选显示当前项目名称 |
| 非 Git 工作区包含 `.gitignore`、`node_modules`、`.runtime` 或其他显式忽略目录 | Runtime 附加忽略行为不作统一保证；daemon 显式忽略目录始终不进入最终候选 |
| 越界路径、外部符号链接、目录、特殊文件 | 不进入文件搜索结果 |
| 工作区内符号链接指向显式忽略目录 | 不绕过显式忽略目录过滤 |
| Runtime 返回较多目录、失效或需过滤结果，最终不足 20 项 | 仅展示通过校验的结果，不把返回上限当作全量枚举保证 |
| 项目不存在、已归档或目录不可用 | 返回对应项目错误；新建会话不是搜索的前置条件 |
| 选中文件后修改或删除，再执行任务 | 读取当前内容，或者明确说明文件不可用 |
| 从 `@` 候选或已有 MCP 菜单选择已启用 MCP | 两个入口均插入“本次请求请优先使用”文案和稳定服务名 |
| 选择已启用 MCP，提交适合其能力的任务 | 真实工具事件可核验；与默认路由冲突时，在权限和上层策略允许的情况下优先使用显式选择 |
| MCP 未启用、未暴露或调用失败 | 未启用服务不进入候选；运行不可用时明确说明，不伪造成功 |
| 文件搜索服务失败 | 有错误状态，正文编辑、MCP 选择和已有任务运行仍可继续 |
| 搜索客户端超时或退出，模型列表与历史查询同时执行 | 搜索失败局限于专用客户端；模型列表与历史查询继续正常工作，后续搜索可按已有机制重启进程 |
| daemon 关闭，搜索尚未启动或已有进行中的请求 | 专用客户端被关闭且不再接收新搜索，不遗留搜索进程 |

自动化测试重点覆盖平台路径语义、显式忽略目录、接口结果、候选键盘操作、Skill 前缀偏移、异步响应竞争和搜索客户端故障隔离。MCP 联调复用现有 `tool_use`、`tool_result` 事件及 `toolCallId`，核对目标服务、调用结果和错误状态；文件引用联调确认 Agent 实际读取的路径与内容，不能只断言模型回复文案。开发完成后按仓库约束运行根命令 `pnpm desktop:preflight:local`，未通过不得宣称可发布。

## 8. 开发基线与待验证事项

本版按统一 `@` 入口，以及 MCP“本次请求优先使用、允许其他工具辅助”的语义推进。纯文本引用、现有任务队列和现有 HTTP/MCP 授权边界继续作为实现基线。

后续开发必须完成的平台与运行验证包括：Windows/Linux 的实际搜索路径语义、中文输入法候选操作、引用文件的真实读取，以及 MCP 显式选择、默认路由冲突和失败场景的真实工具事件。第 4.3 节的 daemon 清理改法在编码前按仓库约束确认。

若未来要求程序级必调用、排他使用 MCP，或文件内容快照，需要另行调整执行层与数据契约，不在本方案中顺带加入。
